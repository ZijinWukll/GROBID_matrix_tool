# 2026-11-06 命令分工与无人值守构建设计

依据本次五项需求执行：PDF 文件夹决定 build 范围；TEI 自动复用；缓存只手动清理；减少重复命令；正常流程无人工必经步骤。

## 选择

只改名称会保留 add/rebuild 与 build 重复的职责；保留多种范围模式也会让缓存旧论文混入。采用单一构建入口，并将导入、离线导出、缓存管理拆为独立动作。

- build：固定扫描 seed_papers，复用有效缓存，自动完成抽取、分类、补译、出表。
- import：从外部复制 PDF，可带 TEI，仅准备输入。
- export：仅导出最近 JSON 快照，服务和 PDF/TEI 缺失时仍可使用。
- status：只读查看。
- cache：查看、预览，只有 clean --apply 才删解析文件；--all 显式包含当前缓存。

add 与 rebuild 作为兼容入口分别映射到 import 与 export；remove 退役。build 取消 input-dir 和 keep-existing，旧源文件应先 import。

## 自动恢复与边界

格式缺失或截断时拆小批次、使用短请求编号、扩大输出预算，最多 repair_attempts 次恢复。网络失败不做逐条无限重试。低置信结果自动检查一次，同标签的更充分结果可采用，分歧不强行放行；已检查过的残留不确定不反复请求。此检查不是独立评测或人工真值。

翻译处理所有缺译，不要求用户按 500 句重复构建，保留引用标记。服务故障或持续无有效进展时停止该阶段并用已有结果出表，状态明确保留未完成项。人工结果永远优先。

## 数据安全和验证

不自动删除缓存，不手改 xlsx，不提交私有状态；手动清理预览后执行，验证绝对路径不越出状态目录。保留短名登记，避免清理后人工覆盖失配。

测试覆盖范围同步、旧/孤立 TEI 复用、导入不构建、JSON 离线导出、清理预览与路径边界、人工数据保护、模型输出恢复、全量补译、自动检查分歧及网络失败保存进度。真实服务验证与自动化测试分开记录。
