# 关键决策

## D-001：数据统一放入 `data/`

配置、状态、种子 PDF 和导出物分别位于 `data/config/`、`data/state/`、`data/seed_papers/`、`data/exports/`。配置内路径保持项目根相对写法，便于定位和迁移。

## D-002：源码只移动、暂不拆模块

现有 `matrix_tool.py` 整体迁入 `src/`，根目录保留薄兼容入口。这样先稳定目录和路径，不把算法拆分与结构迁移混在一次改动里。

## D-003：运行日志与变更记录分开

`log/matrix_tool_YYYYMMDD.log` 是运行日志，按日追加并忽略入版本库；`log/CHANGELOG.md` 记录需要长期保留的版本变更。

## D-004：不再生成 PDF 预览

人工直接审查 `data/exports/` 中的 xlsx。`render_qa.py` 及 `pywin32` 依赖已移除，历史 PDF 文件可以保留但不参与流程。

## D-005：测试以逻辑结果为准

回归测试比较配置语义、译文池和整表逻辑行，不要求 xlsx 二进制完全一致。

## D-006：私有研究数据不进入 Git

真实配置、种子 PDF、TEI/抽取状态、译文池、导出物、回归基线和本机环境快照都只保存在本地。仓库提交目录占位、脱敏示例配置和可公开代码；缺少私有数据时，相关测试自动跳过而不是失败。

## D-007：自动翻译改走本地 vLLM

不再使用 MyMemory。翻译请求通过 OpenAI 兼容接口发送到学校本地模型，连接地址、密钥和模型 ID 由 `.env` 中的 `MATRIX_LLM_BASE_URL`、`MATRIX_LLM_API_KEY`、`MATRIX_LLM_MODEL` 提供；源码只读取环境变量。

## D-008：引用关系采用整格单主标签

每个非空引用段单元格显示一个 `【中文名｜代码】` 主标签，关系方向固定为列论文到行论文。冲突按 `Q&A > C&A > B&E > S&S > M/I` 选择，M/I 作为兜底。模型结果按内容哈希缓存，置信度低于 0.60 或 evidence 完全缺失时进入人工复核清单；`export-labels` 默认只导出待复核项。人工覆盖优先且不会被 rebuild 覆盖。

## D-009：学校服务器地址统一放入 `.env`

GROBID 使用 `MATRIX_GROBID_URL`，本地 vLLM 使用 `MATRIX_LLM_BASE_URL`、`MATRIX_LLM_API_KEY` 和 `MATRIX_LLM_MODEL`。脚本、示例配置和文档不保存学校真实 IP；旧 project 字段仅保留兼容回落。

## D-010：目录批量构建与单篇入口并存

推荐流程为把 PDF 放入 `data/seed_papers/`，运行 `build`；也可用 `--input-dir` 临时指定目录。保留原有 `add`、`--from-tei`、`rebuild` 和人工复核命令，避免改变已有重建的含义。`build` / `add` 自动补齐缺失配置，普通 `init` 创建空项目；旧三篇论文迁移改为显式 `init --migrate-legacy`。

PDF 内容哈希与 TEI 是否存在共同决定是否重新解析；没有哈希的旧记录重新解析一次。按归档路径匹配以保留旧短名、列顺序和人工表头，中文文件名生成带哈希的稳定短名。逐篇保存成功状态，最终统一重建一次；解析失败时继续处理其余论文，并以非零状态结束以支持重试。目录扫描仅限本层，不根据 PDF 缺失自动删除论文登记。

## D-011：build 按当前目录同步，保留历史缓存但不混入矩阵

根据更换整批论文的使用反馈，修订 D-010 的累加默认：`build` 以当前扫描目录为准同步 `paper_order`，不在目录中的论文退出当前矩阵，`papers` 元数据与 TEI/JSON、人工覆盖及译文池保留。恢复同一 PDF 可复用缓存。`--keep-existing` 保留旧累加方式，`add` 与 `rebuild` 的范围语义不变。空目录会清空已有矩阵范围并导出空表；全部 PDF 解析失败时保留上一张表，避免误覆盖。

抽取后模型阶段必须显示进度并限制失败后的连续等待：禁用 SDK 隐式重试，不在网络失败后把一批拆为逐条重试；失败标签保存为可重试的兜底。模型服务失败时优先完成可用 Excel，缺译使用英文，提供 `--no-llm` 直接生成。成功分类和译文按阶段保存，减少中断后的重复工作。
